# Domain Docs

This repository uses a single-context layout.

## Before exploring

Read the root `GLOSSARY.md` and any ADRs in `docs/adr/` that touch the area you are working on. If either location is absent, proceed silently. The `domain-modeling` skill creates these documents as domain terms and decisions are resolved.

## Use the glossary's vocabulary

Use glossary terms when naming domain concepts in issues, refactor proposals, hypotheses, and tests. If a term is missing, check whether the project already uses a different term or flag the gap for `domain-modeling`.

## Flag ADR conflicts

If a proposal conflicts with an existing ADR, cite the ADR and explain what would warrant revisiting the decision.
