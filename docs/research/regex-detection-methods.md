# Secret Wards regex and context methods

Start with format-aware field roles and bounded text rules. Let shape propose a span, use local evidence to assign its role, and check projected edits against protected clinical spans. Compare each addition on the unfamiliar-field holdout. The organizer’s naive regex baseline combined narrow rules with silent skips, so its low score gives limited evidence about the separate contribution of regex. The trials below are proposed and have no measured results. [Candidate pipelines](candidate-pipelines.md) · [Organizer calibration](../SCORING.md#calibration)

## Recognizers and context

Philter defines an explicit order for rules that mark spans as sensitive or safe and uses immediate context to distinguish numeric roles such as age and dosage. pyDeid uses context indicators for ambiguous numeric identifiers and checks potential names against medical terms. These are precedents for scoped evidence in Secret Wards. The papers evaluate English clinical data with different annotation policies. [Philter methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC7156708/) · [pyDeid methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC11752853/)

## Edit precedence and overlaps

Collect proposals before changing a field or text string. Each proposal needs a source location, half-open span in the decoded original, role, rule identifier and supporting evidence. Track edit candidates and protected spans such as a structured observation quantity, a dose and unit, a symptom clause or a clinician mention. An exact protected span can defeat a weak overlapping shape match. Where strong signals disagree, recheck the role in its field or clause. Use the existing unsafe-input boundary if the conflict makes safe release impossible. [Clinical utility and integrity](../SCORING.md#4-clinical-utility-20) · [Challenge meaning traps](../PROBLEM_STATEMENT.md#2-core-challenge-objectives)

Combine evidence for identical original spans. For a nested match, prefer the more specific role with supporting context, such as a labeled Aadhaar-like run containing a phone-shaped substring. For a partial overlap, take the union only when every character in the resulting span belongs to the same sensitive value. Otherwise prefer the grounded boundary or send the conflict to the same check. Use a stable tie order after role and boundary evidence, then apply sorted disjoint edits in one pass over the original string. pyDeid is a precedent for collecting and pruning before replacement. Its broader union rule is a comparator for the overlap fixtures. [pyDeid overlap pruning](https://academic.oup.com/jamiaopen/article/8/1/ooae152/7966802)

## Unicode and performance

The simplest span-safe baseline finds boundaries in decoded source text and normalizes only candidate values and labels for comparisons. NFC is appropriate for canonical equality. Fold decimal digits with `unicodedata.decimal` and remove only recognized separators within the candidate when deriving its digit core. Use a normalization-aware mapped view for cases that require detection across compatibility characters, invisible separators or differently composed text. Unicode normalization can compose, expand and reorder characters. A changed segment needs a source interval, and an endpoint inside such a segment needs a boundary check before editing. ICU’s `Normalizer2.normalizeUTF8` records changed and unchanged ranges through `Edits` and provides a reference for that design. Convert UTF-8 byte offsets explicitly if the adapter slices decoded Python strings. [Unicode normalization forms](https://www.unicode.org/reports/tr15/) · [Python Unicode database](https://docs.python.org/3/library/unicodedata.html#unicodedata.decimal) · [ICU Normalizer2](https://unicode-org.github.io/icu-docs/apidoc/released/icu4c/classNormalizer2.html#details)

Use grapheme boundaries when testing Indic name edits. Python `re` defines `\b` with `\w` and `\W`, so that boundary is insufficient for many strings with combining marks. Test nukta forms, joint letters, mixed-script honorifics, zero-width separators and decomposed accented text beside an unchanged dose. Treat JSON escapes and attachment decoding as adapter operations so the detector’s offsets stay in the decoded value and the adapter controls reserialization. [Unicode text segmentation](https://www.unicode.org/reports/tr29/) · [Python regular expressions](https://docs.python.org/3/library/re.html#regular-expression-syntax) · [Release format contract](../SPEC.md#4-output-layout)

Compile stable patterns once. Dispatch typed fields directly, use narrow bounded windows around cues and apply expensive validation only to proposed candidates. Bound digit and separator counts, and use explicit endings for name and identifier windows. With a fixed rule set, test whether discovery is dominated by repeated scans or by matching itself. Python `re.finditer` returns nonoverlapping matches for each pattern and alternation takes the first branch that matches at a position. Preserve competing hypotheses across recognizers where overlap matters. Compare growth on long near-matches and dense candidates before considering another engine. RE2 guarantees linear match time in input length for a fixed pattern and lacks lookarounds and backreferences. The Python `regex` package adds Unicode properties and operation timeouts. Treat a timeout as an incomplete scan subject to the existing release boundary. [Python `re.finditer`](https://docs.python.org/3/library/re.html#re.finditer) · [RE2 design](https://github.com/google/re2#readme) · [`regex` reference](https://pypi.org/project/regex/)

## Evaluation and score fusion

1. Use the same independently labeled synthetic records for shape-only, shape plus field and local cues, then scope-specific clinical protection. Keep each Patient in one partition and reserve some export templates for the unfamiliar holdout. Score exact typed-span precision and recall, candidate recall before resolution, and exact protected-span retention. Record remaining direct leaks and Canary survival per Scoring Unit, including keys, headers and filenames. Break counts down by role, format, script and familiar versus unfamiliar fields. [Dataset ground truth](../DATASET.md) · [Scoring](../SCORING.md) · [Grouped validation](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)
2. Compare normalizing candidates after matching with a mapped view only if normalization-related misses remain. Check original boundaries, adjacent characters and clinical facts, including newlines around fields. Measure elapsed time, process-tree RSS and candidate counts for enlarged synthetic documents, long digit or mark runs, and dense near-matches. Compare retention against all inputs and track quarantine by reason. Keep the candidate build that improves the targeted slice while meeting the existing clinical and linkage gates. [Sandbox resources](../SANDBOX.md#equal-resources) · [Candidate comparison](candidate-pipelines.md)
3. Keep the initial **Detection Score** ordinal and tied to auditable evidence. If useful candidates survive discovery but lose at resolution, compare the explicit priority rules with an offline candidate ranker. Use field role, shape, local cue, validator state and protected overlap as features. Treat repeated cues from one source as correlated evidence. If there are enough labels, fit a probability calibrator on development predictions from held-out groups and check reliability diagrams with bin counts on a separate holdout. Threshold by role only where there is supporting data and compare direct leaks and clinical edits at each threshold. Report missing candidates separately. Keep detection evidence distinct from the corroboration needed to link two Patient Records.
