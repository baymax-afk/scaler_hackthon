## Export questions for the organizer

| Question | Written guidance and remaining gaps |
|---|---|
| Schema-compatible Patient Pseudonym | For consistency credit, the value claimed in `records.jsonl` must appear inside the corresponding exported Patient Record. The examples show a `patient_ref` column and a `Patient:` note header. CSV must keep its delimiter and header except for renaming a header containing PII. JSON must preserve structure and value types. The FAQ confirms that an existing key containing PII can be renamed. The examples leave the approved placement unspecified when a structured record has no suitable type-compatible field. [Output layout](../SPEC.md#4-output-layout) · [Record consistency](../SPEC.md#6-recordsjsonl) · [FAQ output rules](../FAQ.md#output) |
| JSON locator containing a Direct Identifier | `loc` is the input JSON Pointer. `out` gives the output locator when it differs, and matching uses the longest submitted `loc`. Renaming a key containing PII is permitted. A literal input pointer still contains the original key, and `records.jsonl` is scanned for Direct Identifiers. The organizer would need to specify the accepted privacy-safe `loc` and `out` pair, including whether a parent locator preserves credit when records beneath it belong to different patients. [Record locators](../SPEC.md#6-recordsjsonl) · [Side-channel scan](../SPEC.md#7-behaviour-that-is-scored) · [FAQ output rules](../FAQ.md#output) |
| FHIR Bundle with multiple patients | The kit specifies `doc` for the whole Bundle, one index line per exported Patient Record, and valid R4 with resolvable references. All 19 practice Bundles have one Patient each. The sources leave open whether the evaluator accepts per-Patient entry pointers or another granularity inside a multi-patient Bundle, and where it checks each pseudonym for consistency. [Output layout](../SPEC.md#4-output-layout) · [Record locators and matching](../SPEC.md#6-recordsjsonl) · [Practice FHIR directory](../../dev/input/fhir) |

The local format checker verifies the presence of `file`, `loc`, and `patient` and that `file` was exported. Locator resolution and in-record pseudonym consistency remain evaluator questions even after `CONTRACT OK`. [Public format checker](../../validate_output.py#L91)

## Ranking and runtime

- **Ranking.** The problem statement, FAQ, and fairness document require a margin of more than one point on every hidden dataset. The scoring document instead requires a paired difference significant at 95% and at least 0.5 points. No organizer update identified which wording the leaderboard uses.
