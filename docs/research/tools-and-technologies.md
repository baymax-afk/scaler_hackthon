# Tools and technologies for Secret Wards

A useful baseline to compare is Python's standard parsers and context rules. Unicode-aware `regex`, `phonenumberslite`, `indic-transliteration` (Sanscript), and RapidFuzz are candidates for focused comparisons against that baseline. The kit's checkers and a local FHIR R4 validator can provide development feedback. Tool assessments are based on source review. The measured figures describe the organizer's practice dataset. ## Ingestion and clinical preservation

| Python `csv`, `json`, and `unicodedata` | Stream CSV/TSV rows with explicit delimiter, encoding and `newline=''`. Prefer BOM-aware UTF-8/UTF-16 first, then strict decoding using format evidence for known legacy exports such as cp1252. Check schema and field boundaries before trusting a decode. ## PII detection across English, Hindi and Hinglish

Treat scripts and roles as separate signals. A single note can contain Devanagari name tokens, a Romanized relationship cue and English clinical terms. Field semantics and role cues should lead the decision for names, addresses and identifiers. Match near labels and honorifics, account for initials and order changes, and model clinician, relative and patient spans explicitly. For `C/O`, test both a relative context and a symptom context. Apply the same detection primitives to text, structured values, headers, keys, names of files and directories, metadata and decoded supported attachments. Keep original offsets or an explicit mapping back to the source. ## Cross-script matching and linkage

Transliterate Devanagari name candidates into a consistent Roman scheme and retain the original-script evidence. Produce a small set of comparison forms for vowel length, schwa, honorifics, common abbreviations, token order and initials. Apply these transformations to evidence only, while the sanitized source preserves untouched clinical spans. Unseen spellings and coincident names make transliteration a way to generate candidates, with acceptance based on independent evidence. [Unicode normalization](https://www.unicode.org/reports/tr15/) · [Name and linkage criteria](../DATASET.md#when-must-two-records-be-linked) · [Aksharantar paper](https://aclanthology.org/2023.findings-emnlp.4/)

Fellegi and Sunter formalize record linkage with decisions to link, reject, or defer uncertain pairs. The contest's `null` assignment gives us a similar abstention option. Pair decisions still need an explicit group-level consistency check before being interpreted as patient clusters. [Fellegi and Sunter, 1969](https://doi.org/10.1080/01621459.1969.10501049) · [Record index contract](../SPEC.md#6-recordsjsonl)

Install from a pinned package, then run from local code and tables. Scheme conversion requires a declared convention, so arbitrary Hinglish spelling still needs variant handling. [Upstream source and examples](https://github.com/indic-transliteration/indic_transliteration_py) |

Block on several independent routes, such as exact issuer-scoped MRN or a name form with DOB, relative name, or village and compatible age. It can be installed from a compatible wheel during setup. Raw source storage requires its own at-rest protection. Sanitizer logs and reports should use coarse status codes and counts, and quarantine can use a hash and reason with no copied raw file. ## FHIR R4 validation and attachments

Edit FHIR bundles through a resource-aware JSON adapter. Track rewritten `id` and `fullUrl` values and update the corresponding `Reference.reference` and other identifier-bearing values according to their role. Resolve relative, URN and contained references using R4 rules and validate them locally. Apply text rules to narrative XHTML, reference display, extensions, metadata and supported attachments. Keep R4 type, modifier and required fields intact. FHIR decimals carry significant precision, including trailing zeros, so include a round-trip fixture such as `2.00` with a unit. ## Offline setup and evaluation

1. Pin compatible Linux packages and asset versions, and hash-lock distributions where practical. Stage any models, gazetteers, validator definitions and finite-state data under the repository or its `.venv` during `setup`. The organizer allows network access for the one-time setup and gives it a 30-minute limit. `run` starts with no network and fresh private `HOME` and `TMPDIR`, so verify a clean setup followed by a run from local artifacts with empty caches. Use a local registry for schema references and verify the run also succeeds with the network disabled. [Submission contract](../SPEC.md#1-repository) · [Sandbox](../SANDBOX.md) · [pip repeatable installs](https://pip.pypa.io/en/stable/topics/repeatable-installs/)
2. Measure separately with `validate_output.py`, `check_dev.py` and `check_submission.py --run` using the organizer's synthetic practice data. The contract checker covers the kit's format assertions. It needs the R4 reference and precision tests above for clinical format coverage. `check_dev.py` is a practice proxy for leaks, preservation and links. Compare direct-identifier detection by type, script and hiding channel, and record preservation errors, missing links and false merges. Verify the original input hash and that every input is accounted for. [Contract checker](../../validate_output.py) · [Practice checker](../../check_dev.py) · [Submission self-check](../../check_submission.py) · [Scoring](../SCORING.md)
3. Use `unittest` or `pytest` and optional Hypothesis in development. Generate combinations of safe label renames, field order, Unicode normalization, encodings, ambiguous dates, duplicate keys, nested references and clinical numeric formats. Keep concrete regression examples for past failures. Check release byte reproducibility on `sanitized/` and `records.jsonl`, changes with a different synthetic secret, date interval invariance, and aggregate canary findings across output and side channels. `report.json` includes runtime resource fields, so verify their contract and accuracy independently. [Hypothesis settings](https://hypothesis.readthedocs.io/en/latest/settings.html) · [Contract reproducibility](../SPEC.md#7-behaviour-that-is-scored)
4. Benchmark the complete pipeline on Linux with two CPU cores, a 4,096 MB process-tree RSS budget and a 900-second timeout. Docker with a prebuilt image, `--network none`, CPU and memory limits and a read-only input mount is a local approximation. The organizer samples aggregate process RSS and uses CPU affinity, so measure the whole process tree and record wall time, peak RSS, candidate pairs and the largest blocks. The bundled practice copy has 200 files totaling 626,836 bytes, with a largest file of 20,099 bytes measured from `dev/input/`. Synthetic 10× and 100× corpus runs plus deliberately dense matching blocks and a single large file exercise growth beyond this baseline. The hidden workload size and shape are unknown. [Organizer resource enforcement](../SANDBOX.md#equal-resources) · [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/) · [Docker none network](https://docs.docker.com/engine/network/drivers/none/)
5. Compare privacy policies on synthetic releases using quasi-identifier group sizes and clinical utility by slice. A standard-library counter can report how many distinct patients share a chosen group of released quasi-identifiers. pyCANON (Apache-2.0) can cross-check k-anonymity and l-diversity in development. Anonymeter (Clear BSD) is designed for synthetic-data risk evaluation and requires a separate evaluation design. Report release-level protection using the organizer's scoring definitions and list any proxy metric separately. [pyCANON](https://github.com/IFCA-Advanced-Computing/pycanon) · [Anonymeter](https://github.com/statice/anonymeter) · [Anonymeter license](https://github.com/statice/anonymeter/blob/main/LICENSE.md) · [Organizer scoring](../SCORING.md)

The main unknowns are candidate-pair volume in large shared-name blocks, clinical false positives from compensating for unseen labels, and how often FHIR or attachments need features outside the first adapter. Track each with a holdout slice and compare changes against the rules-first baseline before adding a model, database or validator to the submission runtime. [Unseen-format round](../DATASET.md#the-unseen-format-round) · [Evaluation and scoring](../PROBLEM_STATEMENT.md#6-evaluation--scoring)
