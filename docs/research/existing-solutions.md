# Privacy and clinical utility in existing data releases

Secret Wards requires sanitized patient records from a synthetic multilingual hospital dump. The release must retain its formats and valid FHIR R4 references, use consistent patient pseudonyms within a release, and preserve exact clinical facts and within-patient intervals. Evaluation runs offline with 2 CPUs, 4 GB RAM and 15 minutes per run. Generative models and pretrained transformers above 50M parameters are prohibited. The comparisons below are based on documentation and published results. Runtime, memory use and privacy gains on Secret Wards data remain unmeasured. [Problem statement](../PROBLEM_STATEMENT.md) · [Submission specification](../SPEC.md) · [Scoring rubric](../SCORING.md)

## Release policies compared

NIST SP 800-188 describes release of de-identified records, release of synthetic records generated from source data, protected query interfaces and restricted data enclaves. All can serve research, but they offer different access to individual records. The Secret Wards contract calls for a downloadable tree of sanitized files and a record index. Restricted environments and aggregate query responses are useful reference points for access control and disclosure review. Their deployment would require infrastructure and permissions outside that contract. [NIST SP 800-188](https://csrc.nist.gov/pubs/sp/800/188/final) · [Submission specification](../SPEC.md)

| Policy | Established use and potential benefit | Secret Wards deployment and limitations |
| --- | --- | --- |
| Uniform age and location generalization | In Sweeney’s tabular model, every group sharing the specified quasi-identifiers must contain at least *k* individuals. Applying a common hierarchy is a well-established way to keep categories comparable across the release. [Sweeney, 2002](https://cyberlaw.stanford.edu/content/files/dataprivacy/projects/kanonymity/kanonymity.pdf) | A small fixed set of truthful age bands and geographic levels has low expected compute burden. It needs reliable age and locality mappings and consistent application to structured fields and narrative mentions. Broad bands reduce precision for all affected records, and repeated encounters can inflate cohort counts if counted as independent patients. [Scoring rubric](../SCORING.md) |
| Selective generalization or suppression | ARX implements local and global recoding, cell suppression and record suppression, with documented search strategies and utility measures. [ARX configuration](https://arx.deidentifier.org/anonymization-tool/configuration/) | A release can retain more detail for common groups by coarsening or suppressing quasi-identifiers in smaller groups. The privacy and utility gain is a hypothesis. Local recoding adds decisions and can make disclosure patterns and cohort comparisons harder to interpret. Field suppression needs type and required-element checks. Whole-record suppression loses clinical probes and retention credit, and changing exact diagnoses, procedures or lengths of stay conflicts with the clinical integrity objective. [Problem statement](../PROBLEM_STATEMENT.md) · [Scoring rubric](../SCORING.md) |
| Shared date offset per patient | The credentialed MIMIC-IV v3.1 release shifts each patient’s dates by a single offset and preserves their exact event intervals. It provides a coarse calendar anchor because dates across distinct patients lose direct calendar comparability. [PhysioNet MIMIC-IV v3.1](https://www.physionet.org/content/mimiciv/3.1/) | Translating both interval endpoints by the same offset preserves their difference if they stay on the same time scale. A valid implementation needs consistent application across linked records, reliable date parsing and type-preserving rendering. The exact sequence of gaps remains visible. Secret Wards also checks whether changing the release secret changes the shifts. [Submission specification](../SPEC.md) · [Scoring rubric](../SCORING.md) |
| Calendar coarsening or independent date changes | HHS guidance illustrates retaining only the year under its Safe Harbor example. HHS also describes assessment of disclosure in the context of other available information under Expert Determination. These examples illustrate two approaches to healthcare release design. [HHS de-identification guidance](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html) | The engineering cost of reducing precision is modest when the format permits it. Coarsening clinical event dates can erase exact gaps. Independent shifts can change event order and length of stay. Birth dates can be evaluated separately from clinical event timing because the scoring rubric measures the two differently. [Scoring rubric](../SCORING.md) · [FHIR R4 datatypes](https://hl7.org/fhir/R4/datatypes.html) |

A large *k* on a projected table measures group size on the columns chosen for that projection. The original *ℓ*-diversity paper shows that sensitive values may still be exposed when there is little diversity inside a group or when background knowledge narrows the possibilities. Counting distinct patients prevents multiple encounters from inflating cohort sizes. Clinical facts can support both useful research and uniqueness, depending on what else is released. NIST also documents that *k*-anonymity has no cumulative guarantee for repeated releases. [Sweeney, 2002](https://cyberlaw.stanford.edu/content/files/dataprivacy/projects/kanonymity/kanonymity.pdf) · [Machanavajjhala et al., 2006](https://www.cs.cornell.edu/johannes/papers/2006/2006-icde-publishing.pdf) · [NIST SP 800-188, p. 17](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-188.pdf#page=31)

## Existing tools and evaluation methods

| Reference | Maturity and setup | Fit and limitation |
| --- | --- | --- |
| ARX | Established open-source desktop tool and Java library. Its documented workflow configures column roles and transformation hierarchies, then compares utility and risk. Integration would require a JVM and a tabular projection. [ARX overview](https://arx.deidentifier.org/overview/) · [ARX API](https://arx.deidentifier.org/development/api/) | Suitable as a comparison for tabular generalization and suppression. Its tabular input leaves multilingual notes and the relationships among CSV, JSON and FHIR artifacts outside the tool’s scope. ARX documents a search-time versus solution-quality trade-off. Throughput under the evaluation budget is untested. [ARX configuration](https://arx.deidentifier.org/anonymization-tool/configuration/) |
| Microsoft Tools for Health Data Anonymization | Open-source FHIR tooling first released in 2020, with a .NET command-line tool and configurable, type-aware field rules. [Project repository](https://github.com/microsoft/Tools-for-Health-Data-Anonymization) · [FHIR tool documentation](https://github.com/microsoft/Tools-for-Health-Data-Anonymization/blob/master/docs/FHIR-anonymization.md) | Its rules illustrate selective field handling. Documented date-shift scopes are resource, file and folder, so using the tool for linked histories would still require a verified mapping from dates to patient scope. Its convenience selectors exclude Bundle entries and contained resources from descendant traversal, which calls for explicit coverage checks. [FHIR tool documentation](https://github.com/microsoft/Tools-for-Health-Data-Anonymization/blob/master/docs/FHIR-anonymization.md) |
| Anonymeter | Peer-reviewed PoPETs 2023 framework and open-source research library developed for comparisons of aligned tabular data. The paper reports empirical estimates of singling out, linkability and inference, with controls and uncertainty. [Giomi et al., 2023](https://petsymposium.org/popets/2023/popets-2023-0055.php) | Its empirical estimates reflect the tested assumptions and provide a lower bound on broader risk. A compatible table covers the information represented in it. Whole-release evaluation also needs checks for multilingual notes, artifact leakage and longitudinal records. Runtime and added value on this task remain open. [Anonymeter paper, §4.3](https://petsymposium.org/2023/files/papers/issue2/popets-2023-0055.pdf) · [Scoring rubric](../SCORING.md) |

FHIR release validation belongs alongside measurements of privacy and clinical utility. R4 permits partial `date` and `dateTime` values and requires a time zone and seconds for `instant`. A patient-specific transformation must retain valid primitive values and handle partial dates without inventing exact precision. An identifier or URL rewrite inside a Bundle has to preserve the relationship between resource IDs, `entry.fullUrl` and references. Secret Wards requires internal resolution, so validation can use the emitted Bundle offline. [FHIR R4 datatypes](https://hl7.org/fhir/R4/datatypes.html) · [FHIR R4 Bundle](https://hl7.org/fhir/R4/bundle.html) · [Submission specification](../SPEC.md)

## Optional measurements on synthetic fixtures

- Compare fixed truthful bands and tiers with selective coarsening of quasi-identifiers. Report the number of distinct patients, the fraction in singleton and small groups, the fraction of unresolved patients, and the fraction of records generalized or suppressed. State the projected attributes and definitions. Check exact clinical probes, diagnosis and length-of-stay distributions, lab medians and record retention on the same outputs. [Sweeney, 2002](https://cyberlaw.stanford.edu/content/files/dataprivacy/projects/kanonymity/kanonymity.pdf) · [Scoring rubric](../SCORING.md)
- Compare date policies on a controlled synthetic history appearing in more than one format. Measure exact within-patient intervals, lengths of stay, valid date types and consistency across all records of the same patient. Examine calendar-dependent analyses separately. Check byte-for-byte stability for the same secret and count unchanged pseudonyms and shifts when the secret changes. [PhysioNet MIMIC-IV v3.1](https://www.physionet.org/content/mimiciv/3.1/) · [Submission specification](../SPEC.md) · [Scoring rubric](../SCORING.md)
- Include English, Hindi and Hinglish fixtures, altered layouts, an unresolved link and a malformed file. Track direct-identifier and canary misses in emitted records, filenames, side channels and reports. Check FHIR validity, distinguish clinical loss from quarantine and record peak memory and wall-clock time under the documented limits. Report counts and denominators by language and format where the sample supports it. [Problem statement](../PROBLEM_STATEMENT.md) · [Scoring rubric](../SCORING.md)

The organizers publish calibration for a reference release using per-patient shifts, five-year age bands and other privacy controls. Its reported score drops from 84.84 on the standard normal dataset to 50.33 on the standard chaos dataset. That comparison measures the whole reference submission across two datasets and does not isolate the effect of the date or age policy. The experiments above remain proposals.
