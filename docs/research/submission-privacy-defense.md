# Patient privacy at the submission boundary

## What the release exposes

The submission reads organizer-provided files and a per-release secret. Researchers can inspect every exported record, its filename and directory. The organizer also inspects the index, report, logs and temporary artifacts. A recipient with outside contact or encounter facts may identify a patient even after obvious names are removed. The current implementation writes plaintext output in a private staging directory and publishes the batch by renaming that directory. The organizer requires input SHA-256 fingerprints in the ledger. Anyone who already has a candidate original can compare its fingerprint. Keep that operational report access-controlled when sharing data beyond the competition. ## Evidence from the packaged CLI

The public checker ran the prepared directory three times. It verified the output contract, stable sanitized artifacts on repeat, a changed artifact with a rotated secret, unchanged inputs and no secret in captured output or logs. The rotated artifact check currently exercises path renaming. The organizer's hidden attack arena supplies the actual A1–A7 scores.

The practice run exported 168 of 200 files. Its checker still found 581 visible labels across 3,230 source labels, including 218 patient names and 55 relative names. All 4,382 checked medical probes in exported files survived. The preceding matched-coverage audit counted 4,855 medical probes across all inputs. The practice residual count matches the preceding run. The synthetic regression cases establish the two specific defenses. No aggregate privacy improvement has been measured from them.
