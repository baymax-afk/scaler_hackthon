# Secret Wards V2 robustness techniques

Prioritize the organizer contract, then test narrow improvements to the Phase A rules and release adapters against frozen synthetic cases. Use external tools as comparators or fixture sources where they answer a specific question. The immediate work is to reduce practice leaks and preserve clinical content on unfamiliar inputs, while accounting for files withheld from the Research Release. [Submission contract](../SPEC.md) · [Scoring](../SCORING.md) · [Phase A integration evidence](regex-phase-a-validation.md)

## Organizer baseline and development evidence

- The required interface is an offline run over read-only inputs with two CPUs, 4,096 MB process-tree peak RSS and a standard-profile 900 s hard limit. The standard-profile full-credit thresholds are 60 s and 512 MB. The Research Release contains the sanitized tree and report, plus the record index for linkage credit. Same-input, same-secret repeats must produce byte-identical sanitized files and index. The organizer scans the release and side channels, including filenames, logs, stdout/stderr and private temporary directories. [Submission contract](../SPEC.md) · [Sandbox](../SANDBOX.md) · [Scoring configuration](../../scoring.toml)
- The organizer combines contextual detection, identity resolution, attack resistance, Clinical Utility, format and export integrity, and CPU reliability. Check all six when a change affects the exported records. The organizer’s contextual recall macro-averages by identifier type and script, and contextual precision includes protected clinical traps and clean text. Attack scoring accounts for pooled patient profiles and rare clinical facts alongside direct leaks and release rotation. [Scoring](../SCORING.md) · [Privacy Attack Arena](../ATTACKS.md)
- The Phase A practice run exported 187 of 200 files, with 631 of 3,230 labeled identifier mentions still visible and 4,701 of 4,855 clinical probes preserved across all input. The local Secret Wards Blind fixture run exported 558 of 562 files and had zero visible labeled mentions in its visibility audit. Both corpora informed development and their truth schemas differ. Use them as open regressions. Freeze an independent slice grouped by connected patient, file and template lineage before tuning and keep truth with the evaluator. [Phase A integration evidence](regex-phase-a-validation.md) · [Synthetic datasets](../datasets/README.md) · [Lineage splitter](../../evaluation/splits.py)

## Techniques to qualify

### Schema and source coverage

Use adapter context to distinguish Patient, contact, practitioner and clinical values. Preserve CSV/TSV delimiter, row shape and headers except an identifying header. Preserve JSON structure, value types and number precision. Test reserved key/path escaping, duplicate-key rejection and collisions when renamed keys or paths map to the same output. Account for scalar identifiers represented as JSON numbers, object keys, metadata, filenames and free-text values with unknown roles. Include supported input encodings and exercise malformed, unsupported, oversized and incomplete inputs separately. Track coverage by channel and file disposition. [Submission contract](../SPEC.md#3-input) · [Phase A runtime](../../submission/README.md)

Use typed FHIR paths for `Patient.name`, `Patient.contact.name` and `Observation.valueQuantity`. Scan reference text, identifiers, display values, narratives and supported decoded attachments as separate channels. Keep a resource/reference ledger when a structural identifier or `fullUrl` changes. Reparse output and check resource IDs, relative and URN references, contained references, required elements and dates. Start with organizer Bundle fixtures. Use FHIR R4 and selected ABDM examples to exercise unfamiliar layouts, with profile-specific validation reported separately. A transformed signed document needs an explicit integrity disposition because a signature on the original no longer covers transformed content. [FHIR R4 Patient](https://hl7.org/fhir/R4/patient.html) · [FHIR R4 Observation](https://hl7.org/fhir/R4/observation.html) · [FHIR R4 references](https://hl7.org/fhir/R4/references.html) · [FHIR R4 documents](https://www.hl7.org/fhir/R4/documents.html) · [ABDM DocumentBundle](https://www.nrces.in/ndhm/fhir/r4/StructureDefinition-DocumentBundle.html)

### Normalization and offsets

Keep the decoded source immutable through detection. Build a comparison view only for tested transforms and map matches back to exact half-open original Unicode code-point ranges. Test one-to-many and many-to-one mappings through composition, case folding and digit or separator normalization. Include Devanagari combining sequences, astral characters before a candidate, different line endings, zero-width characters and adjacent protected text. Keep normalization local to comparison because compatibility folding can collapse distinctions in clinical text. Where a decoded payload maps to the whole typed value, validate re-encoding and reparse the written value. Ambiguous source projection requires review and an explicit release decision. Detector offset tests and the organizer's broader leak-normalization check serve different purposes. [Unicode Standard Annex #15](https://www.unicode.org/reports/tr15/) · [Organizer leak counting](../SCORING.md#how-leaks-are-counted-shared-by-several-categories) · [Evaluation driver](../../evaluation/evaluate.py)

### Context, aggregation and clinical hard negatives

Gather candidates on the original source before editing. Combine field role, local positive and negative cues, identifier shape and optional validator or recognizer evidence. Use stable reason codes and separate thresholds for direct action, review and preservation. Track conflicts between roles and candidate/protected overlaps. Deduplicate corroborating matches and verify overlap resolution under different rule orderings. Within a record, a strong label and repeated value can prompt a bounded search for another occurrence. Require local supporting context for each new edit and carry ambiguous repeats to review. Cross-document propagation requires independently corroborated identity evidence and must preserve the role of each occurrence. Masking an earlier match can erase evidence for later rules, so apply the resolved edits once. [Phase A candidate flow](candidate-pipelines.md#proposed-phase-a-detection-flow) · [Presidio recognizer design](https://presidio.dataprivacystack.org/analyzer/developing_recognizers/) · [pyDeid study](https://pmc.ncbi.nlm.nih.gov/articles/PMC11752853/)

Build minimal pairs with the same surface form used in different roles. Include clinician and relative names, complaints and care-of cues, `H/O` and `K/C/O`, wards, standard dosages, blood pressure, `1-0-1` schedules, history durations, eponyms and ASHA terms. Include identifying values within a clinical field beside genuine protected values. Compare exact clinical facts, units, negation and doses before and after. Report both unchanged protected occurrences and all-input coverage so quarantine cannot improve a preservation score by shrinking its denominator. Report errors by label, script, format, role and channel. [Contextual precision](../SCORING.md#1-detection--contextual-intelligence-20) · [Clinical Utility scoring](../SCORING.md#4-clinical-utility-20) · [Phase A audit](regex-phase-a-validation.md)

### Domain randomization and behavioral tests

Vary format, field aliases, role cues, section ordering, document type, issuer, script, code-switching, note length, clinical style and template lineage in synthetic generation. First isolate one variable per pair. Then combine correlated changes and reserve whole patient/template/source families for transfer tests. Sample examples from each slice for human adjudication. Record label, script, note length and section frequencies to locate synthetic distribution gaps. The drift study measured moderate correlation between drift statistics and out-of-distribution F1, while the Indian discharge-summary study found limited transfer in its small local sample and gains from synthetic supplementation in its experiments. These results motivate held-out local slices and targeted synthetic variation. [Measuring the gap](https://pmc.ncbi.nlm.nih.gov/articles/PMC13130710/) · [Indian discharge-summary study](https://aclanthology.org/2024.bionlp-1.26/)

Use CheckList-style minimum-functionality, invariance and directional-expectation cases. An adjacent emoji should move locations by the source coordinate delta and preserve types and clinical values. Canonically equivalent spelling and safely varied separators should preserve the mapped decision for a supported case. Replacing a clinician cue with an unambiguous relative cue should change the expected handling of that occurrence. Randomized properties can cover valid span bounds, edit collision handling, no edits to protected spans, deterministic evidence order and one ledger outcome per input. Retain a minimal replay fixture for any discovered failure. Use property tests at the adapter and detector boundaries, and compare complete outputs when testing run determinism. [CheckList study](https://aclanthology.org/2020.acl-main.442/) · [Hypothesis](https://github.com/HypothesisWorks/hypothesis)

### Release assurance and performance

Gate the staged Research Release on successful reparse, valid reference graphs when applicable, preserved clinical facts, collision-free paths and reconciled reports and records. Verify that every indexed Patient Pseudonym occurs in its exported record. An incomplete scan, uncertain rendering or invalid output should withhold the affected file with a controlled reason. On a synthetic evaluation run, inspect the sanitized tree, output paths, both indexes, optional logs, stdout/stderr and temporary directories for Direct Identifiers and Canaries. Compare input digests, same-secret bytes and release rotation. A format pass and an occurrence score measure different parts of qualification. [Submission contract](../SPEC.md) · [Sandbox](../SANDBOX.md) · [Phase A practice and fixture evidence](regex-phase-a-validation.md)

Measure cold and warm elapsed time, CPU, whole-process-tree RSS and per-stage latency for increasing file counts, text size and candidate density. Record peak memory for concurrent workers and model startup if a comparator uses either. Bound parser nesting, payload decode size, scan work, candidate lists and linkage block size. Record time or size limits as explicit incomplete results and count coverage loss. Profile current precompiled scoped rules first. Trial RE2 on a compatible slow subset only after measuring it, with exact positive, negative and offset parity. RE2's matching complexity bound applies to individual patterns, while parsing, batching, repeated scans and model work need separate measurement. [Organizer CPU scoring](../SCORING.md#6-cpu-efficiency--reliability-10) · [RE2 documentation](https://github.com/google/re2)

### Linkage and temporal transformations

Start with issuer-scoped strong anchors and corroboration. Treat shared household contacts, homonyms, missing values, transliteration and incompatible anchors as explicit cases. Enforce cluster-level conflicts because a chain of plausible pair matches can create a False Merge. Retain Linkage Abstention when support is insufficient. Compare with a blocked Splink experiment on the same synthetic inputs and separate threshold tuning from holdout. Report pairwise F0.5, B³ F1, all three organizer traps, abstention and where blocking lost recall. [Organizer identity resolution scoring](../SCORING.md#2-identity-resolution-15) · [Splink](https://github.com/moj-analytical-services/splink)

For confidently linked Patient Records, compare release-keyed pseudonyms and a consistent per-patient time offset for approved date fields. Use separate derivation contexts for each purpose. Keep date precision and valid format, preserve within-patient event order and intervals, and test leap days, offsets/time-zone boundaries, ambiguous dates and structured/text copies of the same time. Handle DOB, partial dates and unlinked records according to their own release policy and clinical constraints. Measure dates that coincide after rotation because a finite shift range permits collisions. Test age/geography coarsening and targeted suppression on risk-heavy slices, including uncommon facts pooled across records. Duration and rare clinical facts can still distinguish a patient after shifting, so track privacy together with Clinical Utility and input coverage. [Organizer rotation requirements](../SPEC.md#7-behaviour-that-is-scored) · [Privacy Attack Arena](../ATTACKS.md) · [MIMIC date-shift precedent](https://archive.physionet.org/mimic2/mimic2_faqs.shtml)

## Additional primary evidence

- Cross-institution studies found that transfer varies with note type and identifier category. In one study, strict F1 dropped from 0.9547 in the original corpus to 0.8360 on another institution. These figures belong to that study. For V2, hold out complete authoring systems and report exact-span performance by document type. The papers are method references, and their clinical corpora are outside this project. [Cross-institute evaluation](https://pmc.ncbi.nlm.nih.gov/articles/PMC6932867/) · [Transferability study](https://pmc.ncbi.nlm.nih.gov/articles/PMC8633667/)
- Clinical utility can be measured through downstream extraction. An evaluation across 22 note types measured medication-name extraction after de-identification. For V2, use synthetic expected extracts for drug/dose/frequency, negation, labs and temporal facts, alongside exact-span preservation. Treat each downstream measure as specific to the task. [Clinical note utility study](https://pmc.ncbi.nlm.nih.gov/articles/PMC3555323/)
- NIST provides a framework for release risk, pseudonymization and independent review. Its model helps separate ordinary release checks, population-level disclosure risk and reproducible clinical statistics. Follow the organizer waterfall and disposition rules for the judged release. [NIST SP 800-188](https://csrc.nist.gov/pubs/sp/800/188/final)
- Future fusion needs a held-out calibration comparison. Evaluate a deterministic gate, a validation-fitted logistic combination, and model-only and deterministic-only controls. Measure reliability by category where supported and compare paired held-out outcomes, including protection and coverage. A detector's heuristic score has no probability meaning by itself. [Calibration study](https://proceedings.mlr.press/v70/guo17a.html)

## Feasible experiments in order

Freeze a seed, corpus digest, lineage groups, adjudicated source coordinates and protected occurrences before comparing changes. Use Phase A as the engineering baseline and organizer practice as a public regression. Compare paired results over identical inputs, publish numerators and denominators, and mark thin slices inconclusive. Keep thresholds and label mapping fixed before holdout. The proposed sizes are starting points for diagnosing behavior. [Evaluation driver](../../evaluation/evaluate.py) · [Lineage splitter](../../evaluation/splits.py)
